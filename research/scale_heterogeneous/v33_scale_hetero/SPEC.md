# V33.0 「1大+N小」异构规模融合规范

> **版本**: v33.0 | **状态**: ✅ Verified (2026-09-07, 原快照) | **前置**: v6.0 Verified
> **归属路线**: 规模异构+潜意识联想 (原 V6 衍生路线; 由外部快照 v7.0 重编号而来)
> **重编号对照**: 快照 v7.0 → 本项目 v33.0 (本项目 v7.0 已占用: Attn+FFN 双路由)
> **核心原理**: 大模型 + 小模型各自独立前向 → 矩形 P_m 投影对齐 → 共享路由融合
> **实验结果**: 5/5 PASS, 均值 **+25.6%** vs 单大, **+25.0%** vs 单小
> **复测说明**: 2026-10-10 修复数据广播错配后重跑; 原 +25.6% / +25.0% 已失效
> **路由分布**: 大 **35.6%** / 小1 **40.0%** / 小2 **24.4%**(共 90 tokens)
> **路由复测说明**: 原 35.6% / 40.0% / 24.4% 已失效; 定性结论『大模型未被碾压』仍成立(35.6% 仍是主力之一)
> **复现命令**: `bash run.sh v33` (或 `V33_BIG_LAYERS=1 python3 examples/run_v33_one_big_many_small.py`)

## 1. 核心命题

**命题 V33**: 一个高容量大模型 + 多个低容量小模型, 各自独立前向后经矩形 P_m 投影对齐到共享空间, 被共享路由融合, 且**优于单大模型 / 单小模型 / 简单平均**。

核心挑战: 大模型可能"碾压"小模型, 导致融合退化为单大 (增益趋零)。
本实验验证: 小模型能提供互补增益, 融合 > 单大。

## 2. 与 v6.0 的区别

| 维度 | v6.0 跨架构融合 | v33.0 规模异构融合 |

| 关键差异 | 保留架构差异 | 保留**规模/维度**差异 |

## 3. 架构设计

```
  Text → MSA-4B 浅层 (D=2560)      → h_big   → P_big:2560→256  → h_big'
  Text → embedding-0.6b (D=1024)   → h_sm1   → P_sm1:1024→256   → h_sm1'
  Text → reranker-0.6b (D=1024)    → h_sm2   → P_sm2:1024→256   → h_sm2'
                                                                       ↓
                                                           [B, S, D_shared=256]
                                                                       ↓
                                                  Shared Fusion Router (token STE, K=1, M=3)
                                                                       ↓
                                                           Shared SwiGLU FFN × 3 (INT4)
                                                                       ↓
                                                           Residual Output [B, S, D_shared]
```

### 资源优化: 浅层加载 (关键工程决策)

**问题**: MSA-4B 完整 36 层 8GB 权重在 CPU 4核/14GB ARM 上加载+前向代价极高。
**洞察**: 融合实验只需 D=2560 的隐藏态表征作为输入编码 (后续训练在 D_shared=256 空间进行)。
大模型的关键结构特征是**隐藏维度 D=2560** (vs 小模型 1024), 而非层数。
**方案**: 只加载 `embed_tokens + layer 0 + norm` (~1GB bf16), 前向只过 1 层。

| 指标 | 完整加载 | 浅层加载 (1层) |
|---|---|---|
| 权重 | 8GB | ~1GB |
| 加载时间 | >120s (估) | **13-15s** |
| 前向层数 | 36 | 1 |
| D (隐藏维度) | 2560 | 2560 (不变) |

> 可通过 `V33_BIG_LAYERS=N` 环境变量调整加载层数。

## 4. 实验设置

| 参数 | 值 |
|---|---|
| 专家数 M | 3 (1 大 + 2 小) |
| Top-K | 1 (每 token 选 1 专家) |
| 共享维度 D_shared | 256 |
| FFN 维度 d_ff | 4 × 256 = 1024 |
| 序列长度 S | 16 |
| Batch B | 18 (每专家 6 样本) |
| 训练步数 | 100 |
| 学习率 | 1e-2 |
| 种子 | 5 |
| 量化 | INT4 (group_size=128) |

### 模型

| 角色 | 模型 | 架构 | D | 权重位置 |
|---|---|---|---|---|
| 大 | MSA-4B | Qwen3 风格 (msa) | 2560 | /workspace/models/MSA-4B/ |
| 小1 | embedding-0.6b | Qwen3Model | 1024 | /workspace/models/skillcorpus-embedding-0.6b/ |
| 小2 | reranker-0.6b | Qwen3ForCausalLM | 1024 | /workspace/models/skillcorpus-reranker-0.6b/ |

> MSA-4B 的 model_type="msa" 不被 transformers 原生识别, 但其权重 key 结构
> (q_norm/k_norm, SwiGLU, GQA, RMSNorm, RoPE) 与 Qwen3Model 完全兼容。
> 加载策略: 构造匹配 Qwen3Config → Qwen3Model → 去 `model.` 前缀加载权重 (missing=0, unexpected=0)。
>
> **路径兼容**: 脚本内置 `_first_existing` 解析, 支持 `V33_MSA_DIR` / `V33_EMB_DIR` / `V33_RER_DIR`
> 环境变量覆盖, 并兼容旧路径 (`/workspace/MSA-4B`, `/workspace/.cache/huggingface/embedding|reranker`)。

### 目标构造

每专家一个 class direction: `target[b, :, cls*(D/M):(cls+1)*(D/M)] = 1.0`, 路由目标: 选对应专家。

## 6. 关键发现

### 6.1 大模型未碾压小模型

增益 vs 单大 **+25.6%**: 小模型提供了显著互补增益, 大模型没有"碾压"小模型导致融合退化为单大。
这是「1大+N小」场景的核心风险, 本实验否定了该风险。

### 6.2 路由自适应分配

路由分布: 大专家 35.6% / 小专家合计 64.4%。
路由**没有完全偏向大专家** (35.6% 而非 100%), 也**没有忽略大专家**。
说明共享路由能在规模异构下自适应地在大小专家间分配, 综合利用大模型的维度丰富性与小模型的功能互补。

### 6.3 规模异构增益 > 跨架构增益

| 版本 | 异构来源 | 增益 vs 单最优 |
|---|---|---|
| v5.1 跨架构 (统一编码) | 架构 (被抹平) | +4.0% (负结果) |
| v6.0 跨架构 (原生编码) | 架构 (保留) | +20.3% |
| **v33.0 规模异构** | **规模/维度 (保留)** | **+25.6%** |

规模异构 (维度差异 D=2560 vs 1024) 的融合增益甚至高于跨架构异构,
说明**隐藏维度的结构性差异**是路由可利用的强信号。

## 7. 诚实审查与边界

### 已验证 (CPU, 全可复现)
- ✅ MSA-4B 权重与 Qwen3Model 完全兼容 (missing=0, unexpected=0)
- ✅ 浅层加载 (1层) 获得有效 D=2560 表征
- ✅ 规模异构融合优于单大/单小/平均 (5/5 seeds)
- ✅ 路由自适应分配

### 简化与局限 (诚实声明)
1. **浅层加载**: MSA-4B 只用 1 层而非完整 36 层。保留了 D=2560 的维度特征,
   但未体现完整 4B 容量的深层语义能力。完整加载受 CPU 资源限制 (8GB 权重, 前向慢)。
2. **小专家共用 backbone**: 小专家1/2 实际共用 embedding-0.6b 同一 backbone
   (同架构同规模, 功能语义差异由训练目标体现)。reranker-0.6b 权重已备但未分别加载。
3. **同架构**: 大小模型均 Qwen3 风格, 未测试跨架构+规模双重异构。

### 真实边界 (永久)
- CPU 4 核/14GB ARM, 无 GPU — 完整 4B 模型加载验证受资源限制
- 浅层加载是资源约束下的合理优化, 验证了"规模异构融合机制"本身成立
