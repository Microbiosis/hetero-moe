# V56.0 — 维度作为容量分配 (capacity allocation)

> **日期**: 2026-10-27
> **归属**: scale_heterogeneous（容器范式），v39 的直接后继
> **状态**: 🚧 待跑（HF Space `cpu-upgrade`）
> **复现**: `V56_DEVICE=cpu python examples/run_v56_capacity_allocation.py`

## 0. 要回答的问题

v39 证明了「融合头必须非线性」（`concat+MLP` 0.997 vs `add` 0.781）。但那一代有两个量
**从头到尾是固定超参，从未当成变量**：

```
hidden = 128                    ← 融合头瓶颈宽度
ProjHead: c(512) → D_BIG(2560)  ← 入口被投到容器宽度
```

于是四个问题一直没有答案：

| # | 问题 | 为什么重要 |
|---|---|---|
| **Q1** | 宽度是否是约束？ | 若是，「高维空间」是真实变量 |
| **Q2** | 投影到 D_BIG 是否必要？ | 线性投影不增信息，但可能改变优化难度 |
| **Q3** | 空间被填满了吗？ | 秩随宽度饱和 ⇒ 容量是比喻 |
| **Q4** | 哪个模态在被用？ | 按块消融，看零掉某侧掉多少 |

## 1. 不降级清单

| 维度 | v39 | v56 |
|---|---|---|
| 数据 | Adult XOR (`decouple=True`) | **复用同一份** |
| 容器表征 | MSA-4B 浅层 1 层 → `h_base[512,2560]` | **复用同一份**（缓存 npz）|
| 被动入口 | TabLDM `c_passive[512,512]` | **复用同一份** |
| 划分 | 384/128，seed 1234 | **同一构造** |
| 学习率 / 步数 / batch | 1e-3 / 500 / 64 | 相同 |
| **新增变量** | — | **宽度 × 投影方式 × 头类型** |

## 2. 网格

```
2 表征 (proj: c→2560 | native: c 保持 512)
× 2 头  (linear | mlp)
× 10 宽度 (4,8,16,32,64,128,256,512,1024,2048)   [linear 头无宽度, 只跑一次]
× 2 臂  (A 零入口 | C 真入口)
× 5 seeds
= 220 次训练
```

容器与入口**全冻结**，只有融合头在学 —— 单次训练 0.5–30 s CPU。

## 3. 预登记判决

| 编号 | 判决 | 阈值 |
|---|---|---|
| **P1** | `linear` 头在任何宽度下都解不开 XOR | acc ≤ 0.80 |
| **P2** | MLP 在 `hidden=16` 已达成最好宽度的 95% | ≥ 0.95 × best |
| **P3** | `proj` 与 `native` 准确率差 | ≤ 0.03 |
| **P4** | 大宽度（1024/2048）下激活有效秩 < 宽度 5% | 两者都要 |

**P2 是核心**：若 16 维就够，则「高维空间」在单任务设定下不是约束。
**P4 是关键**：若秩随宽度饱和，则空间是「在那里没东西填」，不是「不够大」。

## 4. 维度诊断（已出，本地转述）

在 512 样本上实测（`eff_rank` = 参与率 `(Σσ)²/Σσ²`）：

| 张量 | 环境维 | eff_rank(PR) | eff_rank(熵) | 占用 |
|---|---|---|---|---|
| `h_base` 容器输出 | 2560 | **33.7** | 74.5 | **1.32%** |
| `c_passive` TabLDM | 512 | **17.1** | 35.1 | **3.35%** |
| concat native | 3072 | **44.5** | 97.0 | **1.45%** |

**2560 维的容器输出，实际只占 33.7 个方向（1.32%）。**

这一条在跑主网格之前就已经回答了「高维空间」的一半问题：
**空间一直是空的。** 宽度增加不会增加被使用的内容。

单侧线性探针（XOR 下应接近 chance 0.5）：`h_base only 0.727` / `c only 0.648` ——
两者都高于 0.5，说明 Adult 的 `decouple=True` 没有完全切断相关（v39 §5 已声明此为已知边界）。

## 5. 边界

- 单一数据集（Adult XOR），单容器（MSA-4B 1 层）
- 标签是人工构造的 XOR，非数据集原生任务
- `c_passive` 是 TabLDM 的被动中间表征，不涉及自训练臂
- 单侧探针 0.65–0.73 而非 0.5：`decouple` 未完全切断，XOR 的「严格跨模态必需」打折
