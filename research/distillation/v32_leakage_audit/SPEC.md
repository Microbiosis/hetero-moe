# V32.0–V32.4 — 目标泄漏审计 (target-leakage audit)

> **本文件是包内权威规范。** 机器可读声明见 [`MANIFEST.json`](MANIFEST.json)，
> 指标快照见 [`results/metrics.json`](results/metrics.json)，
> 权威测试见 [`tests/test_package.py`](tests/test_package.py)。

## 0. 这一代做什么

v32 **不引入任何新机制**。它是审计代：把 v16 蒸馏头条结论里混杂在一起的三种效应
拆开，分别复测，然后如实公布其中一种承担了全部表观收益。

| 效应 | 原本的猜测 | 审计结果 |
|---|---|---|
| 教师前向随机性的 Jensen 型方差平均优势 | 学生拟合条件均值，天然优于单次教师采样 | **不可测量** |
| 损失里的 0.3 直接目标项（目标泄漏） | 未被单独识别 | **承担全部 +0.159 表观收益** |
| 真正的概念方向迁移 | 蒸馏的本质主张 | **测不到** |

## 1. 为什么必须做这件事

v16 记录的表观结果是学生 `0.135` 对教师 `0.257`（+47.5%），看起来是"单教师蒸馏
可行，学生能超过其多底座教师"。但损失函数里除了蒸馏项，还加了一项权重 0.3 的
**直接目标项**：

```
L = 0.7 · MSE(y, y_teacher)  +  0.3 · MSE(y, y_target)
                        ↑ 概念方向            ↑ 训练期才有的真值信号
```

第二项在部署时不存在。**训练时给学生看真值、测试时不给**，得到的收益无法归因于
"蒸馏"。v32 的全部实验都在回答一个问题：**把第二项移走，学生还剩多少优势？**

## 3. 核心数字

无泄漏条件（β_h = 0，deterministic 教师，10 seeds）：

```
教师      0.3231 ± 0.0146
纯学生    0.3240 ± 0.0130
配对差   -0.0009 ± 0.0038     不显著
```

对照混合条件（同协议）：

```
混合学生  0.1647 ± 0.0070     ← 论文头条里的 "学生超越教师"
```

**读法**：负的配对差 = 学生比教师差。所以"纯蒸馏不超越教师"，而混合条件下的优势
完全由那个 0.3 的真值项产生。

> ⚠️ **两个容易引错的口径**
> 1. 配对差是 `teacher − student`，**不是** `student − teacher`。反过来会读成"学生反超"。
> 2. 标准差是**样本**标准差（ddof=1）。用总体标准差会得到 ±0.0036，与论文的 ±0.0038 不符。
> 3. 头条数字取自 `deterministic` 条件，不是 `base`。两者数值不同。

## 4. 为什么本包要自带原始记录

`results/v32_*.json` 这四份记录原本只存在于**仓库根的 `results/`**——而那个目录是
.gitignore 的原始实验输出，克隆仓库的人拿不到。也就是说，论文里最关键的那个
负结果，其证据链在分发版本里是断的。

本包把四份记录一并带上，于是结论变成**可重算的**：

```bash
python -c "from research.distillation.v32_leakage_audit import leakage_verdict; print(leakage_verdict())"
```

`audit.py` 只依赖标准库，只读包内 `results/`，不碰 torch/numpy，也不引用仓库根。
任何人拿到这个目录就能独立复核，无需相信作者的自述。包内测试 8 项，其中
`test_headline_number_reproduces_paper` 就是钉住"重算出的 −0.0009 ± 0.0038 与论文一致"。

## 5. 对 v16 / v17 的影响

| 代 | 原判定 | 审计后 |
|---|---|---|
| v16 | 单教师蒸馏可行，学生超越教师 +47.5% | `leakage_audit.status = invalidated`，收益全部归因于泄漏项 |
| v17 | 多教师蒸馏全部退步 | 负结果本身不受泄漏影响，仍成立 |
| v18 | 真实语料上的修正评估 | held-out MSE 0.157 属混合目标下的读数，同样受泄漏项影响 |

论文已把这一条写进正文与五条负结果之一，并明确标注"未修正的说法最可能招致审稿人
质疑"。

## 6. 边界

全部结论只在 **CPU 规模、合成数据**下成立。准确表述是"**该规模下测不到**概念方向
迁移"，不是"概念方向迁移不存在"。规模前沿是本项目明确写下的开放问题。
