# V49.0 — 投影空间的三重检验: 非线性 × 条件依赖 × 样本量

> **日期**: 2026-10-25
> **状态**: 🚧 运行中 (15 格 = 3 样本量 × 5 臂 × 5 seeds, HF Space 远端)
> **复现**: `bash run.sh v49` (本地 CPU) / HF Space `redmingwei/hetero-moe` (远端, 每格一跑可续跑)
> **一句话**: v48 说"让投影可训练"得到的是**拟合能力**而不是融合增益; v49 把
> **非线性 / 条件依赖 / 样本量**三条轴同时做成 2×2 析因 + 样本量自变量, 看它们
> **互相印证**还是互相替代。

---

## 1. 为什么是这三条轴

| v48 的发现 | 留下的悬案 | v49 的做法 |
|---|---|---|
| 冗余存在 (CKA 0.48) 但联合 PCA 抓不到 (足迹重叠 <0.06) | 那份额外结构要靠**非线性**才能用; 而 v48 的 B 臂 P_m 是**线性**的 | **轴 N**: 线性 vs 非线性抬升, 隐藏维按参数量反解 → 参数差 <0.3% |
| "空间要随条件改变"从未实现 | 条件依赖 = 投影由**内容派生条件**经超网络低秩调制 | **轴 C**: 静态 vs 条件依赖 + **打乱条件 (shuffle-c)** 判决性对照 |
| 18-36 样本 vs 1.18M 参数 → 必然记忆 | 记忆 vs 真对齐, 靠样本量区分 | **轴 S**: 32 / 256 / 1024 (组合式槽位生成器, 训练与留出**文本零交集**) |

## 2. 设计与三个"交叉照应"的判据

### 2.1 析因结构

```
        静态 C0        条件依赖 C1
线性 N0   L_static      L_cond
非线性 N1 NL_static     NL_cond
(外加 L_static_frozen = v48 的 A 臂, 作为"投影冻结"基线)
```

**容量对齐** (v41 教训): 线性臂 `d_shared×D_m` vs 非线性臂 `D_m·h + h·d_shared`,
`h` 按参数量反解 → 两臂参数量差 **<0.3%** (D_m=2560: 655,360 vs 656,617;
D_m=1024: 262,144 vs 262,861)。**N 轴的差异不能被"参数更多"解释。**
条件依赖臂额外多 V/U/超网络 (+7~8%); 该轴的判决性对照不是参数量而是 shuffle-c。

**算力对齐**: 固定 minibatch (288/步) + 固定步数 (300) → 样本量轴测的是
**固定算力下的数据多样性**, 不是算力。

### 2.2 三条交叉判据 (这是"交叉照应"的具体形式)

1. **记忆 vs 对齐**: 若 B 轴收益全是记忆 → 过拟合间隙随 S 增大而**收窄**,
   且 held-out 增益随 S 增大而**上升**; 若增益不随 S 变化 → 容量假象。
2. **非线性是否真在抓那份结构**: 若 N 轴在抓非线性冗余 → N 的增益应**随 S
   增大而放大** (样本少时非线性只会更快地记忆); 否则 N 的作用就是多参数。
3. **条件是否真在用**: shuffle-c 必须显著退化; 且退化幅度应随 S 增大而
   **减小** (样本多才学得出可迁移的条件调制)。若 N 与 C 是同一机制 →
   两者同开时增益**不可叠加**; 若正交 → 可叠加。

### 2.3 任务与数据

- 任务: **跨底座同目标** (8 类 × 32 维块) —— 同一文本在三个底座上目标相同
  → 必须跨底座对齐才能做对 (v48 的 Task-S 在 3 类文本上区分不出, 这里用
  8 类 + 组合式文本重做)。
- 数据: `data.py` 的槽位组合生成器 (每类 16×16=256 种组合, 训练池/留出池
  **各 128 且完全不相交**); 档位嵌套 32⊂256⊂1024。
- 底座: MSA-4B 浅层 1 层 (D=2560) + embedding-0.6b (D=1024) +
  reranker-0.6b (D=1024), 各自原生 tokenizer。

## 3. 结果 (HF 远端, 5 seeds, held-out fuse MSE, 越低越好)

平凡基线 (预测全零) = **0.1250**; 括号内为过拟合间隙 (in-sample→held-out)。

| 臂 | S32 | S256 | S1024 |
|---|---|---|---|
| **L_static_frozen** (投影冻结, v48 的 A 臂) | 4.830 (+4.5%) | 4.742 (+2.8%) | 4.795 (+2.5%) |
| **L_static** (线性可训练) | 1.167 (+93.6%) | 0.515 (+81.1%) | 0.440 (+74.1%) |
| **L_cond** (线性 + 条件) | 1.190 (+96.6%) | 0.507 (+84.8%) | 0.435 (+76.9%) |
| **NL_static** (非线性可训练) | **0.118 (+41.9%)** | 0.097 (+23.5%) | 0.093 (+15.6%) |
| **NL_cond** (非线性 + 条件) | 0.148 (+91.3%) | 0.087 (+57.8%) | **0.080 (+50.4%)** |

**「融合 vs 单专家」的相对增益** (同一张表, 换一种读法):

| 臂 | S32 | S256 | S1024 |
|---|---|---|---|
| L_static_frozen | **+60.6%** | **+65.8%** | **+64.4%** |
| 其余四个可训练臂 | +0.9% ~ +2.5% | +0.5% ~ +9.8% | +0.7% ~ +2.6% |

**shuffle-c 退化** (打乱条件后 held-out 变差多少):

| 臂 | S32 | S256 | S1024 |
|---|---|---|---|
| L_cond | +2.7% | +6.2% | +7.2% |
| NL_cond | +24.6% | +47.0% | **+50.3%** |

### 3.1 三条交叉判据的裁决

1. **记忆 vs 对齐**: 线性臂的间隙随 S 收窄 (+93.6%→+81.1%→+74.1%) 而 held-out
   同步下降 → 它**既有记忆成分也在学**; 但**非线性臂的间隙低一半** (+41.9%→+23.5%
   →+15.6%) 且 held-out 低 5-10 倍 → **非线性臂的收益不是"多记了一点"**。
2. **非线性是否真在抓那份结构**: N 轴的增益**随 S 增大而收窄** (9.9× → 5.3× → 4.7×)
   —— 恰好与"样本多时线性也能慢慢学到一点"一致; 而**非线性臂在 S32 就已接近平凡
   基线** (0.118 vs 0.125) → **样本量轴的收益被非线性轴吃掉了**。
   参数量对齐 (<0.3%) → 差异不能被"参数更多"解释。
3. **条件是否真在用**: shuffle-c 退化随 S **增大** (NL_cond: +24.6%→+47.0%) →
   条件学得**越来越实**, 不是装饰。但**在 S32 上条件反而有害**
   (NL_cond 0.148 > NL_static 0.118) → **条件依赖需要数据**。
   N×C 交互存在且**随 S 变号** (S32: C 在 N 上有害; S256/S1024: C 在 N 上有帮助)。

   ★ **最有意思的一条: 条件依赖只在非线性基座上起作用。** 线性基座上 C 几乎
   没有效果 (L_cond vs L_static: 1.190/1.167, 0.507/0.515, 0.435/0.440 — 三档
   都在噪声内), 而**配上非线性后 C 才开始加分** (NL_cond vs NL_static:
   0.148/0.118 有害 → 0.087/0.097 → **0.080/0.093** 变好)。
   合理解释: 条件调制是**低秩**的 (rank=16), 它只能给映射加一点"随内容偏转";
   在线性映射上这点偏转无处发挥 (线性 + 低秩偏转 ≈ 还是线性), 必须先有
   非线性底座, 条件调制才有一个"非线性函数"去偏转。

### 3.2 一条贯穿三臂的负面结论 (本代最尖锐的一条)

**一旦投影可训练, 「融合 vs 单专家」的相对增益就塌到 ~0** (可训练臂 +0.5%~+9.8%
vs 冻结臂 +60.6%~+65.8%), 且**与样本量无关** (三档都塌)。

→ **v33 架构的"融合"收益并不来自融合**: 投影空间一可训练, 单专家基线同步变强,
融合的相对优势被摊平。这条与 v48 在小样本上的观察 (+0.0%) 一致, 现在在
**参数量对齐 + 三档样本量**下复现。⚠️ 该主张需独立审计包结清 (v50)。

### 3.3 最好的一格与"平凡基线"参照

**最佳格: NL_cond @S1024 = 0.0798** —— **低于"预测全零"的平凡基线 0.125**,
即融合后的输出确实比什么都不做更接近目标。而冻结臂 (4.795) 差平凡基线 **38 倍**。

### 3.4 与 v48 的对接: 空间该多大, 口径要改

v48 的"并集 95% 方差维数 = 28"是在 48 个 token 上估的; v49 用 **8192** 个 token
重估为 **4** (99% 方差 19 维, 有效秩 38) → v48"空间过配 5-14 倍"的说法
**偏保守**, 实际过配更大 (当前 D_SHARED=256 vs 数据 4-19 维)。
同时 v49 的 CKA 口径 (8192 token) 给 CKA 均值 **0.2545**, 置换零分布上限均值
**0.0008** → 三对底座 (0.234 / 0.100 / 0.430) **全部远超零分布**,
**"冗余存在"的结论在 170 倍多的样本上依然成立, 而且更干净**。

⚠️ 但要注意: 组合式文本的类内结构比真实语料规整得多, 所以"数据只有 4 维"
这个读数**不能**外推到真实语料; 能外推的只是**趋势** (非线性 > 线性、条件
需数据、可训练后相对增益归零)。

### 3.1 诊断 (样本量大了统计量才站得住)

| 量 | v48 (48 token) | v49 (256 token) |
|---|---|---|
| 并集 99% 方差维数 | 47 | 34 |
| 并集 95% 方差维数 | 28 | **5** |
| 并集有效秩 | 27.2 | 24.3 |
| CKA 均值 (零分布上限) | 0.481 (0.253) | 0.256 (0.026) |

> ⚠️ 95% 维数从 28 掉到 5: v48 的 48-token 估计**严重高估**了数据维数 ——
> 组合式文本 (每类同构) 的方差结构远比自由文本低。**这说明 v48 的"空间过配
> 5-14 倍"这个结论要用 v49 的口径重算。**

## 4. 诚实声明

1. **任务仍可能不够"要求对齐"**: 8 类 × 32 维的目标块, 单底座也可能自己
   学会 (它的特征里就有类别信息) → 必须同时看"vs 单专家"的相对增益, 不能只看
   绝对 MSE。
2. **条件由输入内容派生**: 条件里含类别信息 (输入本来就含), 这不是标签泄漏
   (与输入同源), 但它使"条件轴"与"容量轴"部分纠缠 → shuffle-c 是唯一判决。
3. **组合式文本是合成分布**: 槽位组合的类内结构比真实语料规整, 绝对数值
   不可外推到真实语料; 只有**趋势** (随 S / 随 N / 随 C 的变化方向) 可外推。
4. **底座浅层**: MSA-4B 只取 1 层 (与 v33/v48 一致), 未体现 4B 深层语义。
5. **两个小专家**: 阶段 2 沿用 v33 构造 (小1/小2 共用 backbone) 时不成立 ——
   本代用的是**真正不同的** embedding/reranker 两个模型 (与 v49 的诊断一致)。

## 5. 远端复现基础设施 (踩过的坑)

- 编码输出是 **bf16** (底座按 bfloat16 加载) 而投影器是 fp32 → 必须显式
  `.float()`, 否则 `F.linear` 报 dtype 不匹配。
- Space 会被**回收重启** → 单次跑完 15 格等于白跑: 改成**每格一个 combo**,
  跑完一格落一格 (桶里 `state.json` 记状态, 重启后自动续跑下一个)。
- `app.py` 的 combo 名含 ":" 时才解析 protocol/task → 自定义 combo 曾因引用
  未定义变量而崩; 现改为"两段同时喂给 v48 与 v49 的 runner"。
- 产物目录按代分开 (`V48_ART_DIR` / `V48_BUCKET_PREFIX`), 避免 v48/v49 互相覆盖。
