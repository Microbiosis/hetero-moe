# V48.0 — 投影空间: 该多大 / 可不可训练 / 会不会自己变

> **日期**: 2026-10-25
> **状态**: ⚠️ 部分 Verified (诊断 + 可训练性 A/B 已有数据; 条件依赖变体未做)
> **复现命令**: `bash run.sh v48` (本地 CPU) / HF Space `illusion-brain/hetero-moe-v48-runner` (远端)
> **一句话**: **v33 旗舰结果的"投影空间"是随机正交且冻结的 —— 它根本没被学过。**
> 本代量化了"空间该多大"、并把"投影可训练"从猜想变成可测量的对照。

---

## 0. 起点: 一个实现审计发现的事实

v33 (`CrossModalFusionLayer`) 的跨架构投影是:

```python
self.P_m = nn.ParameterList([nn.Parameter(torch.empty(d_shared, D_m)) ...])
for m in ...: nn.init.orthogonal_(self.P_m[m])       # 随机正交初始化
# 专家 FFN (w_gates/w_ups/w_downs) 同样被冻结
```

而 runner 里 `layer.P_m[m].requires_grad_(False)` 再冻一次。
**全流程真正被训练的只有** `W_router` + 每专家 `(γ, β, α)` ≈ 2.3K 参数。

即: v33 报告的 "+25.6% vs 单大" 是在一个**几何完全随机、且从未被训练**的
共享空间里取得的。投影空间这个变量, 在旗舰结果里**根本没被检验过**。

> 这正是"空间必须可训练、必须自己变动"这个直觉的落点 —— 它命中的是
> 一个真实的空白, 而不是重复 v10/v13 已经做过的对齐器路线。

## 1. Q1: 空间该多大? (training-free 诊断)

"所有底座的并集刚好装下" 是可计算的。`space.py` 给出:

| 量 | 做法 | v48 实测 (扩展协议 P2, 3 底座 × 48 token) |
|---|---|---|
| 并集有效维数 | 叠放各底座中心化表征 → 谱, 相对阈值 | **99% 方差 47 维 / 95% 方差 27 维 / 有效秩 26.9** |
| 每底座内在维 | 单底座谱 | big 43/38 (99%/95%), small1 38/18, small2 18/5 |
| 跨底座语义冗余 | linear CKA + 置换零分布 | 见 §1.2 |
| 共享空间的三指标 | K 网格 (联合 PCA): 保真度/冗余度/重叠度 | 见 §1.3 |

### 1.1 关键读数: 现在的空间严重过配

`D_SHARED = 256`, 而数据实际占用 **5–47 维** (95% 方差口径 5–38 维)。
即**共享空间比数据的有效维度大 5–14 倍**。这从数据侧支持了"刚好合适"的
直觉: 现用的 256 维不是"装下并集"所必需的, 而是随手取的。

### 1.2 关键读数: 底座之间**共享几何结构**, 但**线性方法抓不到它**

用 **linear CKA**（对正交变换不变；典型相关在 n<p 区间天然被抬到≈1、没有分辨力）
加**行置换零分布**作对照 —— 观测值必须超过零分布上限，才算"真共享"。

> ⚠️ 本节数字由 HF 远端重跑给出（CKA 口径）。**先前归档在 `results/metrics.json`
> 里的 `canonical_correlations` 用的是有 bug 的白化矩阵**（写成了 `(U/s)@Vᵀ`，
> 那不是白化），据此得出的"几乎没有共享结构"是**错的**，已作废。

| 底座对 | CKA | 置换零分布上限 | 判定 | top-8PC 上的 CC1（零分布上限） |
|---|---|---|---|---|
| big × small1 | **0.537** | 0.406 | ✔ 超零分布 | 0.932 (0.790) |
| big × small2 | **0.318** | 0.211 | ✔ 超零分布 | 0.911 (0.806) |
| small1 × small2 | **0.588** | 0.143 | ✔ 超零分布 | 0.960 (0.872) |
| **均值** | **0.481** | 0.253 | | |

→ **三个底座确实共享大量几何结构**（CKA 均值 0.48，远高于零分布上限 0.25）。

**但 K 网格显示：在联合 PCA 共享空间里，三个底座的足迹重叠始终 < 0.06**（§1.3）。
两者合起来的含义是本代最关键的一条：

- 冗余**存在**，但**线性最优方法都找不到它** —— 联合 PCA 就是线性最优的，
  它抓不到，说明这份额外结构不是"一个共同的线性子空间"那么简单，
  要靠**逐底座不同的非线性映射**去利用。
- 这正好解释了 v10 的现象：**注意力对齐器比线性 P_m 好 +67%**，
  原因不是"多了一个空间"，而是**注意力是非线性的、能找到线性方法找不到的重叠**。
- 于是"空间必须可训练、必须自己变动"这句话有了精确形式：
  **要拿到那份重叠，空间的映射必须能学，而且必须能学到非线性的部分；
  固定线性 P_m（无论冻结还是训练）都只能看见线性可对齐的那一小块。**
- ⚠️ 但注意 **B 臂的 P_m 是线性的** → 它学到的也只是线性对齐；
  实验显示它主要在**记忆**（过拟合间隙 95%–99.9%）。要区分"记忆"与
  "真学到了非线性对齐"，必须扩样本 + 加正则 + 上条件依赖臂（§3/§5）。

### 1.3 K 网格: 保真度 / 冗余度 / 重叠度

| K | 保真度min | 冗余度 | 重叠度(足迹) |
|---|---|---|---|
| 8 | 0.381 | 0.743 | 0.057 |
| 16 | 0.502 | 0.578 | 0.027 |
| 32 | 0.645 | 0.452 | 0.013 |
| 48 | 0.655 | 0.370 | 0.009 |

读法:
- **保真度**随 K 单调上升但**在 K=48 仍只有 0.66** —— 因为 48 已是 token
  行数的上限 (48 个 token 最多撑起 47 个独立方向), 不是"更大就更好"。
- **冗余度** (共享方向的实际占用比) 从 0.74 掉到 0.37 → K 越大越空。
- **重叠度** (足迹重叠, 迹内积) 始终 < 0.06 → **三个底座在联合 PCA 共享
  空间里几乎不占相同方向**。这与 §1.2 指向同一件事: **底座间的重叠不是
  "被发现"出来的, 必须被"造"出来** —— 这正是"空间必须可训练"的最硬依据。

## 2. Q2: 投影可训练有没有用? (三臂 × 2 任务 × 2 协议 × 5 seeds)

三臂**参数量完全相同** (解冻不增参数, 只增自由度) → 不受 v41 审计的
容量混杂影响:

| 臂 | 可训练 | 说明 |
|---|---|---|
| **A_frozen** | W_router + (γ,β,α) | v33 现状复现 |
| **B_train_proj** | + P_m | **只有投影会变** → "空间自己会学" |
| **C_train_all** | + P_m + 专家 FFN | 全部可训练 |

两个任务**严格配对** (输入逐位相同, 只有目标语义不同):

- **Task-T** = v33 原任务: 目标 = 专家身份块 (只考路由)
- **Task-S** = 新任务: 目标 = 文本类别块 (同一文本在三个底座上目标相同)
  → **必须跨底座对齐**才能做对

两个协议: **P1** = v33 逐位复现 (3 类 / S=16 / 每底座 6 样本);
**P2** = 扩展 (6 类 / S=4 / 每底座 12 样本, padding 占比 80%→25%)。

### 2.1 结果 (held-out fuse MSE, 5 seeds)

**权威数字来自 HF 远端复跑**（Space `redmingwei/hetero-moe`，5 seeds，held-out fuse MSE）：

| 协议·任务 | A 冻结 | B 投影可训练 | C 全可训练 | 平凡基线(全零) | B vs A | C vs A |
|---|---|---|---|---|---|---|
| P1·Task-T | 8.82 | **2.05** | 4.08 | 0.332 | **+76.8%** | +53.7% |
| P1·Task-S | 8.94 | **2.27** | 3.75 | 0.332 | **+74.6%** | +58.1% |
| P2·Task-T | 9.99 | **4.55** | 4.46 | 0.332 | **+54.5%** | +55.4% |
| P2·Task-S | 9.79 | **4.72** | 4.68 | 0.167 | **+51.8%** | +52.3% |

**跨机可复现**：本地 CPU 跑出的同组数字（A 8.40 / B 2.07 / C 3.58 @P1·Task-T）
与 HF 远端（A 8.31 / B 2.05 / C 4.08）**逐组一致到 ~1%**，两台机器结论相同。

### 2.2 三条必须一起读的结论

1. **绝对误差: B 显著优于 A (降 52%–77%)**。让投影可训练确实让空间更有用。
2. **但过拟合间隙 95%–99.9%** (B 的训练集 MSE 0.005–0.11, 留出 2.1–4.7):
   投影把空间变成了**记忆器**。18–36 个训练样本 × 1.18M 个投影参数,
   记住是必然的。
3. **"融合 vs 单专家"的相对增益归零** (B: +0.0%; A: +7.4%~+22.8%)。
   因为单专家基线用的是**同一个投影**, 投影一变, 所有下游一起变好。
   → **B 的收益全部来自"拟合能力", 而不是"融合机制"。**

### 2.3 附带发现: v33 基准的绝对质量

所有臂的绝对 MSE 都**远高于"预测全零"的平凡基线** (A: 8.9 vs 0.33 = 27×;
B: 2.1 vs 0.33 = 6×)。即已发布的 "+25.6% vs 单大" 是**两个都很差的模型
之间的相对比较**。这不否定 v33 的结论 (它测的是相对增益), 但引用时必须
带上这个绝对参照 —— 否则会高估该基准的强度。

### 2.4 任务语义不影响结论

Task-T 与 Task-S 的结果几乎相同 (A: 8.94 vs 9.11; B: 2.07 vs 2.29) →
这套架构的性能由**路由 + 冻结随机专家**主导, 与"是否需要跨底座语义对齐"
无关。**要检验投影空间, 需要一个真正依赖对齐的任务** —— Task-S 还没能
把它区分出来 (留出文本是手工改写, 6 个小模型对它们的区分度有限)。

## 3. Q3: 空间"自己变动" (条件依赖) —— 未做, 但已定型

用户命题: "空间必须是可训练的, 能够随着条件的改变而改变"。
拆成三层, 本代只做了第 0 层 (可训练), 后两层是下一步:

| 层 | 变的是什么 | 形式 | v48 状态 |
|---|---|---|---|
| L1 训练期变 | 坐标矩阵 | 梯度学 | **已做 (B/C 臂)** → 收益来自拟合, 过拟合 |
| L2 条件依赖 | 坐标随 c 变 | `P(c)`: 超网络 / FiLM | 未做 |
| L3 结构性变 | 空间重组 (槽/维度) | slot attention / SLATE / 可增长码本 | 未做 |

**L2/L3 必须带的对照** (否则不可判定):

- **打乱 c**: 打乱条件的标签在样本间的对应 → 性能应退化回静态水平;
  若不退化, 说明空间"在动但没用"。
- **同 c / 错配 c**: 错配应显著变差 → 证明空间真的是条件依赖的。
- **未见条件泛化**: 训练只见条件 A/B, 测试换新条件 C → 区分"真机制"与
  "条件 ID 查表"。
- **等参数量**: 超网络/槽系统的参数 vs 静态等价容量 (v41 的教训)。
- **双口径** (in-sample / held-out): v46 指出老 runner 全在训练同源数据上
  评估, 会假绿 —— v48 已在每一臂都同时报两个口径。

**L2 的一个具体理由**: 并集的维数是**条件依赖的** (不同文本/模态的并集
维数不同), 所以"刚好合适"不该是全局常数, 而应逐样本/逐条件自适应 ——
这正是 L3 (可增长/可收缩的槽) 的动机。

## 4. 本代修掉的工程问题 (顺手记)

1. **训练批量化**: v33 逐样本循环 (18 次小算子/step) 在本机 CPU 上 100 步
   要 432s (瓶颈是 ~100 万次小 kernel 启动, 不是算力)。融合层本身与批维
   无关, 故改为批量化, **损失语义等价**, 提速约两个数量级。
2. **谱估计的伪零特征值**: p≫n (4608 vs 48) 时, p×p 的 Gram 有 4761 个
   ~1e-15 的数值零特征值, 会把 K_aff 算成几百。改用 n×n 的 Gram (非零谱
   相同但无伪零), 并把 MP 地板降级为参考项 (对模型输出常失效), 主估计
   改用相对阈值维数。
3. **白化矩阵写错** (`(U/s)@Vᵀ` 不是白化, 正确是左奇异向量 U): 导致
   典型相关被压低, 一度误判成"底座间没有共享结构"。已改用 linear CKA +
   置换零分布, 并由 2 项单元测试守住。
4. **远端复现基础设施** (HF Space `redmingwei/hetero-moe`): 三个坑 ——
   (a) `transformers==4.44` 导不进 `Qwen3Model` → 容器秒退 (Dockerfile 改成
   装支持 Qwen3 的版本线, 并在镜像里做导入自检);
   (b) 漏拷 `hetero_moe` 包 → `FakeQuantSTE` 缺失, 4 个组合全在 import 处挂;
   (c) 状态页线程设成 daemon → main() 一返回进程退出, 被 HF 判 RUNTIME_ERROR。
   另: 状态 `state.json` 存桶而非容器内, 否则 Space 重启后幂等续跑失效。

## 6. 诚实声明

1. **诊断的统计量很弱**: 只有 48–96 个 token 行, 谱/维数估计噪声大
   (MP 地板、K_aff、elbow、eff_rank 四个估计彼此能差 5 倍)。结论只取
   "数量级"意义 (数据占 5–47 维, 而非 256 维), 不取精确值。
2. **C 臂的学习率是分组给的** (大矩阵 1e-3, 路由器 1e-2): 用主 LR 时
   C 臂在 100 步内发散 (MSE → 2.7e5)。A 臂不含大矩阵, 行为与 v33 一致,
   可比性不受影响。
3. **B 臂的过拟合无法区分"投影有潜力"与"参数记住了样本"**。要区分必须
   扩样本量 (P2 只有 36 样本/底座) 或加正则。
4. **小专家 1/2 共用同一 backbone** (沿用 v33 构造, 以与已发布数字可比),
   所以 "两个小专家" 在表征上完全相同, 只有 P_m 不同。阶段 1 的诊断用
   的是三个真正不同的编码器 (含 reranker), 两者的差别已在 §4 标注。
5. **P_m 的梯度只经残差项回传** (v33 的 `_compute_output` 对专家通路做了
   `x_det = x_shared.detach()`), 所以 B 臂的学习信号比"直觉上"弱得多。
   这是 B 臂的一个**结构性上限**, 不是调参问题。
6. 归档在 `results/metrics.json` 的 `canonical_correlations` 字段使用了
   有 bug 的白化矩阵, **数值偏低, 不可引用**; 正确口径 (CKA + 零分布)
   需按 §5.1 在 HF 远端重跑后回填。
