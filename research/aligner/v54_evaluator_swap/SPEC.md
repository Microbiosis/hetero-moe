## 0. 出发点: 基线是 chance level, 不是拟合出来的参照

v53 的目标块是 **[n, S, D] 的块状 one-hot**: 每个样本恰有一个 block 宽 `D/n_classes` 的
区段置 1。因此

```
MSE(预测全零) = 置 1 元素占比 = (D/n_classes) / D = 1 / n_classes      ← 精确等式
```

**v53 的真实 n_classes 是 6**(不是记录里的 8, 见 `v53_third_audit/CORRECTION.md`):

| 基线 | 精确值 |
|---|---|
| 预测全零 | **0.166667** |
| 预测类别均值 `(n-1)/n²` | **0.138889** |

v53 有意义空间臂 held-out = 0.1617 → 比全零好 3.0%, **但比"预测类别均值"差 16.4%**。
即: 它还没有真正学到类别结构。这种量级上比较"融合 vs 最优单专家", 比的是两个同样坏的模型。

**MSE 作为点估计对"这个模型根本没在建模分布"没有分辨力** —— 这正是 v52 观察到
"逐位相同的 7.527/7.527" 无法被 MSE 区分的根因。本代不改数据、不改臂, **只换尺子**。

## 1. 不降级清单 (预登记, 事后不得修改)

| 维度 | v53 (基线) | v54 (本代) | 关系 |
|---|---|---|---|
| 数据生成 / 值域分割 | v53 | **import 同一份** `v53_third_audit.make_split` | 逐位相同 |
| 三族探针 | ridge/mlp/knn | **import 同一份** `probe_accuracy_all` | 逐位相同 |
| 抬升 | Residual/Linear | **import 同一份** 两个类 | 逐位相同 |
| 臂 | 4 | 4 (同构同义) | = |
| seeds | 2000–2004 | **同一批, 三档共用** | = 且**配对** |
| steps / n_per_class / tokens | 200 / 16 / 6→8 | 200 / 16 / 8 | ≥ |
| n_classes | **6** | **6** | = (修正后的真实值) |
| D_shared | 96 / 384 | **96 / 252 / 384** | ⊇ 严格包含 |
| 评价器 | MSE | **MSE + 高斯NLL + CE** | +2 |

**"配对"是不降级的核心**: 三档在同一 (arm, D, seed) 下各自 `torch.manual_seed(seed)` 重建模型,
权重**逐位相同**(有单测), 批顺序由同一个 `Generator` 种子决定。任何两档的差异只能来自损失函数。

网格 = 3 (D) × 4 (臂) × 3 (评价器) × 5 (seeds) = **180 次训练**。

### 1.1 一个硬约束: 256 不可用

块状 one-hot 要求 `D_shared % n_classes == 0`, 否则 block 不等宽、`reshape` 会**静默错**。
v52 的 256 在 8 类下可用, 在 6 类下**不可用**(256/6 不整)。最近的同量级合法值是
**252 = 42×6**。runner 与 `EvaluatorHead` 都在入口处断言, 传入非法值直接报错并给出最近合法值。

## 2. 参数等量纪律 (v49 起立的规矩, 各臂参数差 <1%)

换评价器最容易踩的坑: **输出头尺寸变化会偷偷改变参数量**, 于是"哪把尺子好"和"哪个模型大"
混在一起。三档必须逐参数同构(单测 `test_param_parity` 守住):

| 评价器 | 输出 | 到 loss 的路径 | 额外参数 |
|---|---|---|---|
| **MSE** (对照) | `[n,S,D]` | 直接对目标块算 MSE | **0** |
| **CE** | `[n,S,D]` → block-mean pool → `[n,S,K]` → softmax → **摊回 `[n,S,D]`** | cross-entropy | **+1** (可学习温度 τ) |
| **高斯 NLL** | `[n,S,D]` + `Linear(D→1)` 逐样本标量 `logvar` | `0.5·(e^{-lv}·err + lv)` | **+D+1** |

CE 不另接一个 `D→K` 线性头, 而是 **block 均值池化 + 温度**, 让 lift 主体的输出张量逐字节相同。

### 2.1 CE 必须把输出压到单纯形上 (冒烟抓到的坑)

CE 不约束输出幅度, 那个张量的 MSE 与 MSE 档**不可比**。冒烟实测: 未压时 CE 臂
`fuse = 1.97`(而基线 0.1667), 压到单纯形后落回 `0.1528`, 与 MSE 档的 `0.1525` 同量级。

压法: block 均值 → softmax → 概率摊回各自 block → `pred` 是"预测的 one-hot"。

**内部一致性检查**(单测 `test_ce_uniform_matches_predict_mean_baseline`):
温度极大时 softmax 均匀, 其 MSE 恰等于 `predict_mean` 基线 `5/36 = 0.138889`,
CE loss 恰等于 `ln 6 = 1.791759`。两条独立推导撞到同一个数, 说明三档真的同量纲。

### 2.2 推理读数也必须过同一层头

训练时 CE 的输出过了单纯形投影, 推理时若直接用融合层的裸输出, 比的还是不同量纲的东西。
runner 的 `to_eval()` 把同一层头作用到 `fuse / avg / best_single / 探针输入` 上。

## 3. 预登记判决 (先写死, 事后不得改)

| 编号 | 判决 | 阈值 | 失败意味着 |
|---|---|---|---|
| **E1** | 有意义空间臂的绝对误差在 **三档全部** 低于冻结随机臂 | 3/3 档, ≥4/5 seeds | 评价器仍在决定结论, 结论不可信 |
| **E2** | 冻结随机臂在 **CE** 下准确率 ≈ `1/6 ± 0.05` | ≥4/5 seeds | 冻结臂并非处于 chance 水平 |
| **E3** | 有意义空间下"融合 vs 最优单专家"的 **CE 准确率差 ≤ 5pp** | ≥4/5 seeds | 若某档变正, 需单独解释 (不算通过) |
| **E4** | NLL 臂 `logvar` 与平方误差 Spearman ≥ 0.2 且为正 | ≥4/5 seeds | 方差头退化成常数 → E2/E3 的 NLL 读数作废 |
| **E5** | 投影空间有效秩: 有意义空间 > 冻结随机空间, 三档同量级 | 两个 D 都要 | 空间仍是低秩退化解 |

**E4 是自检, 必须在读 E2/E3 之前过。** 常数 logvar 下秩相关无定义, 若不设哨兵
`argsort` 会给一个"看起来正常"的假相关 —— 已修 (`_spearman` 对零方差返回 0, 有单测)。

## 4. 算力与"不降级"的关系

用户已定: **t4-small (1×T4 / 4 vCPU, ~$0.60/h)**, 三档全跑。

钱花在 `encode_all`(三个冻结底座把全量文本编一遍), 不在几千参数的 projector 上。
代码 device-agnostic (`V54_DEVICE`), 升档不改代码路径。

**缓存不算降级**: 按 `(文本集哈希, 底座, dtype)` 缓存编码是 bit-identical 的等价变换。
省下的机时**全部加到网格上**(1 档 → 3 档, 2 个 D → 3 个 D), 不是缩短网格。

跑完即退: `V54_MAX_MINUTES` 兜底, 不留常驻循环 (沿用 v48 的算力教训)。

本地实测限制: 冒烟 (12 格 / 8 steps) 首次 42s, 但沙箱在高负载下会退化到每格数分钟
(3s → 329s)。180 格的整格跑**不在本机做**。

## 7. 冒烟实测 (2026-10-27, D=96, 1 seed, 8 steps, 伪编码)

> 冒烟只为把训练/判决/血缘链路跑通, **不产生任何结论**。但它暴露了两个结构性问题,
> 都是真问题, 已修/已登记。

### 7.1 已修: CE 输出必须压到单纯形, 且推理读数必须过同一层头

| 版本 | CE 臂 held-out `mse` 读数 |
|---|---|
| 未压 + 推理不过头 | **1.9702** (基线 0.1667) |
| 压到单纯形, 推理**不过**头 | 0.7407 |
| 压到单纯形 + 推理过头 | **0.1500** |

三档配对后: `mse 0.1504 / gauss_nll 0.1507 / ce 0.1500` —— 同一量级, 差 <0.5%。
这说明**"三档不可比"是实现的错, 不是评价器本身的错**。

### 7.2 新登记: E1 对 CE 档在结构上不成立 → 新增 E6

CE 档的**冻结随机臂**拿到 `mse = 0.1389`, 恰等于 `predict_mean` 基线。
原因: CE 头在随机特征上饱和到**均匀分布**, 而均匀分布正是零参数最优常数预测器。

> 于是 CE 下"随机冻结臂"不是坏模型, 它自动退化成一个聪明的常数预测器。
> E1 的 "learned < frozen" 在 CE 档比的是**两个都不是坏模型的东西**。

**E1 保留不改** (预登记纪律); 新增 **E6**: 有意义空间臂必须严格低于**该档自己的零参数基线**。

冒烟读数: 三档 learned 均为 `+8.0%~+8.5%` vs `predict_mean` 基线 → **E6 未过** (8 steps 欠训练,
全网格 200 steps 才是判决点)。这条恰好证明换尺子的价值: **MSE 下看着"低于全零"的空间,
在正确基线面前是正的。**

### 7.3 尚未验证

- E4 (方差头未退化) 在 8 steps 下未过 —— 正常, 需 200 steps
- E5 (有效秩) 未实现自动计算, 需在全网格产物上单独跑
- 冒烟用伪编码, 真实底座编码下的量级可能整体位移 (基线是解析值, 不受影响)

## 8. 实验完整性机制 (全网格开跑前冻结)

> 这一节的机制**已就位并通过自检**, 且在 180 格开跑**之前**写好。
> 目的是让"预登记"从一句承诺变成可被第三方验证的事实。

### 8.1 协议锁 `protocol.lock.json`

`tools/freeze_protocol.py` 生成, 固定两样东西:

| 固定项 | 内容 | 防的是什么 |
|---|---|---|
| **网格** | D={96,252,384} × 4 臂 × 3 评价器 × 5 seeds(2000–2004) × 200 steps × 16/class × 8 tokens × batch 288 | 看到结果后偷改网格 |
| **判据** | `PREDICTIONS_V54` 的 sha256 (`20c6ae18d313b4e3`) | 看到结果后偷改预登记判据 |

runner 开跑前对拍, 不一致**直接拒绝执行**; 唯一出口是显式 `V54_ALLOW_DEVIATION=1`,
且偏离会写进产物 (`protocol_check.diff`), 不会静默。

锁自身的 `sha256 = 559ec41467efeb3a`。核对: `python tools/freeze_protocol.py --check`。

### 8.2 配对指纹 `init_sha` (产物级证据)

"三档配对"原来只有单测保证 —— 单测证明的是**代码逻辑**, 不是**这一次运行的产物**。
现在逐 `(arm, D, seed)` 对共享初始化 (projs + layer, 不含 EvaluatorHead) 做哈希,
三档必须给出同一个值。检查器 L5 从产物层核对。

冒烟实测: `D96 / learned_lift / seed=2000` → 三档均为 `11a403e6675c88a0` ✓

### 8.3 血缘 `code_sha`

- 干净树 → `2f4119a`; 有未提交改动 → `2f4119a+dirty` (**脏跑会被标出来**)
- 检查器 L2 用 `git merge-base --is-ancestor` 判定"产物出自本仓库历史中的某个提交",
  而不是"等于 HEAD" —— 文档/工具提交晚于产物是正常情况

### 8.4 冒烟与结果分离

产物自己声明性质 (`protocol_check.status == "smoke"`), 检查器据此:
- 跳过网格-锁对拍 (冒烟本就不是网格)
- 但**仍然校验判据指纹** —— 冒烟也必须用同一套预登记判据

### 8.5 本轮修掉的一个自身违规

写这一节时发现: 首次入库的冒烟产物出自 `4023ee5+dirty` (加 E6 之前),
而代码已推进到 `6b808e3`。**产物里 verdicts 缺 E6、predictions 只有 E1–E5。**
这正是我上一轮批评 v53 的那个病, 我自己复发了。

处理: 删除该产物 → 提交 → 在干净 HEAD 重跑 → 重新入库 (`code_sha=2f4119a`, 无 dirty)。
教训: **"检查器"不能只指向别人; 每次改完代码都要把产物重跑一遍。**
