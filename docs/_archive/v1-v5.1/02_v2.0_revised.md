## 1. 架构前提与张量对齐

假设融合 $M$ 个具有相同 Transformer 架构规格的预训练模型作为异构底座。

- **隐藏层维度严格对齐**：$d_{model}$ 一致，残差流 $h \in \mathbb{R}^{B \times S \times D}$ 无障碍流入任意层。

## 2. Triton Kernel 的数学与算子级修正

v1.0 的核心错误在于用逐元素乘法替代矩阵乘法。修正后使用 `tl.dot` 并引入 Tiling 策略：

```python
import triton
import triton.language as tl

@triton.jit
def fused_hetero_swiglu_kernel(
    x_ptr, out_ptr,
    w_gate_ptr, w_up_ptr, w_down_ptr,
    router_ptr,
    S, D, D_FF, M: tl.constexpr,
    BLOCK_D: tl.constexpr,
    BLOCK_FF: tl.constexpr,
):
    pid_b = tl.program_id(0)
    pid_s = tl.program_id(1)

    x_offsets = pid_b * S * D + pid_s * D + tl.arange(0, BLOCK_D)
    x_mask = tl.arange(0, BLOCK_D) < D
    x = tl.load(x_ptr + x_offsets, mask=x_mask, other=0.0)
    x_2d = x[None, :]
    acc = tl.zeros((BLOCK_D,), dtype=tl.float32)

    for m in range(0, M):
        r_offset = pid_b * S * M + pid_s * M + m
        router_weight = tl.load(router_ptr + r_offset).to(tl.float32)
        if router_weight > 1e-6:
            h_act = tl.zeros((1, BLOCK_FF), dtype=tl.float32)
            for ff_start in range(0, D_FF, BLOCK_FF):
                ff_offsets = (m * D * D_FF) + tl.arange(0, BLOCK_D)[:, None] * D_FF + (ff_start + tl.arange(0, BLOCK_FF))[None, :]
                w_gate = tl.load(w_gate_ptr + ff_offsets).to(tl.float16)
                w_up = tl.load(w_up_ptr + ff_offsets).to(tl.float16)
                h_gate = tl.dot(x_2d, w_gate)
                h_up = tl.dot(x_2d, w_up)
                h_act_chunk = (h_gate * tl.sigmoid(h_gate)) * h_up
                h_act = h_act + h_act_chunk

            down_offsets = (m * D_FF * D) + tl.arange(0, BLOCK_FF)[:, None] * D + tl.arange(0, BLOCK_D)[None, :]
            w_down = tl.load(w_down_ptr + down_offsets).to(tl.float16)
            h_out = tl.dot(h_act, w_down)
            acc += router_weight * tl.reshape(h_out, (BLOCK_D,))

    out = x.to(tl.float32) + acc
    tl.store(out_ptr + x_offsets, out.to(tl.float16), mask=x_mask)
```

**已知缺陷**：`h_act` 累加器维度错误，`w_down` 未参与 D_FF 维度分块，边界 Mask 完全缺失。此 kernel 仍为概念示意，不可编译运行。

## 3. 路由 Loss 的数学修正

### 3.1 负载均衡损失 (Load Balancing Loss)

$$ f_m = \frac{1}{B \cdot S} \sum_{b,s} \alpha_{b,s,m} $$

$$ P_m = \frac{1}{B \cdot S} \sum_{b,s} \mathbb{1}[m \in \text{TopK}(\alpha_{b,s})] $$

$$ L_{balance} = M \cdot \sum_{m=1}^{M} f_m \cdot P_m $$

### 3.2 Z-Loss (Router Logit 稳定)

$$ L_{z} = \frac{1}{B \cdot S} \sum_{b,s} \left( \frac{1}{M} \sum_{m=1}^{M} z_{b,s,m}^2 \right) $$

**已知缺陷**：此公式实为 L2 正则化，非标准 Z-Loss。标准 Z-Loss 应为 $\frac{1}{BS}\sum(\log\sum\exp(z))^2$。

## 4. 跨异构底座的分布对齐策略

采用逐层仿射适配器结合残差门控：

$$ h_{aligned} = h_{in} \odot \gamma_m + \beta_m $$

其中 $\gamma_m, \beta_m \in \mathbb{R}^D$ 是针对第 $m$ 个模型专门学习的逐通道缩放和偏移参数。参数量为 $2 \times D \times M$。

同时，将该 FFN 的输出注入回主干残差流时，使用零初始化的标量门控 $\alpha$，确保训练初期底座输出分布不被破坏：

$$ h_{out} = h_{in} + \alpha_m \cdot FFN_m(h_{aligned}) $$

**已知缺陷**：$\alpha_m$ 零初始化会导致训练初期梯度死锁，Router 无法接收主任务梯度。

## 5. 显存驻留与量化调度

底座 INT4 仅权重量化，显存占用降至约 14GB。Kernel 内部 Dequantize-on-the-fly：

```python
# 伪代码：在 Kernel 内部反量化
w_gate_int4 = tl.load(w_gate_ptr + offsets, dtype=tl.uint8)
w_scale = tl.load(w_scale_ptr + scale_offsets)
w_gate_fp16 = (w_gate_int4.to(tl.float32) - 8.0) * w_scale
```

**已知缺陷**：未处理 INT4 packing（两个 4-bit 值 per byte）、group-wise 量化参数加载、以及 bank conflict 问题。
