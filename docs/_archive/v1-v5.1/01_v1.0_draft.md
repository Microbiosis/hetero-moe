## 1. 架构前提条件与张量对齐

假设融合 $M$ 个具有相同架构规格的模型（例如 Llama 架构，$d_{model} = 4096$，$d_{ff} = 11008$，$layers = 32$）。

为避免引入额外的投影矩阵（nn.Linear）导致信息损耗和显存开销，必须满足硬性约束：

- **隐藏层维度严格对齐**：所有模型的 $d_{model}$ 必须一致，确保残差流 $h \in \mathbb{R}^{B \times S \times 4096}$ 可以直接流入任意模型的任意层。
- **词表对齐**：使用相同的 Tokenizer，确保输入索引 $x \in \mathbb{Z}^{B \times S}$ 映射到不同模型的 Embedding 层时不会发生语义错位。

---

## 2. 算子级数学模型

标准 Llama 的 SwiGLU FFN 计算如下：

$$ FFN(x) = (\text{SiLU}(x \cdot W_{gate}) \odot (x \cdot W_{up})) \cdot W_{down} $$

在微观融合中，将 $M$ 个异构模型的第 $i$ 层 FFN 视为 $M$ 个独立的计算路径。引入一个门控网络 $G(x)$，输出形状为 $[B, S, M]$ 的路由权重。

对于残差流中的某个 Token 向量 $x_t$，其经过融合层后的输出为：

$$ y_t = x_t + \sum_{m=1}^{M} \alpha_{t, m} \cdot FFN_m(x_t) $$

其中 $\alpha_{t, m} = \text{TopK}(\text{Softmax}(x_t \cdot W_{router}))$，只激活概率最高的 $K$ 个模型以保持稀疏性，降低计算复杂度。

如果在这一步直接使用 PyTorch 的 torch.einsum 或 nn.Linear 进行循环计算，会产生 $M \times 3$ 个中间激活矩阵（形状为 $[B, S, 11008]$），在 $M=4$ 时这将瞬间耗尽 24GB 显存。

## 3. Triton 算子级融合：显存驻留策略

最底层的融合要求：中间激活值不写回 HBM（显存），直接在 GPU 寄存器或 SRAM 中完成加权累加。

我们需要编写一个 Triton kernel，在同一个执行流中完成权重加载、矩阵乘、SiLU 激活、逐元素乘、门控加权与残差连接。

```python
import triton
import triton.language as tl

@triton.autotune(
    configs=[
        triton.Config({'BLOCK_SIZE': 512}, num_warps=4),
        triton.Config({'BLOCK_SIZE': 1024}, num_warps=8),
    ],
    key=['SEQ_LEN'],
)
@triton.jit
def fused_hetero_swiglu_kernel(
    x_ptr, out_ptr,
    w_gate_ptr, w_up_ptr, w_down_ptr,
    router_ptr,
    B, S, D, D_FF, M,
    BLOCK_SIZE_D: tl.constexpr,
    BLOCK_SIZE_FF: tl.constexpr,
):
    pid_b = tl.program_id(0)
    pid_s = tl.program_id(1)

    x_offsets = pid_b * S * D + pid_s * D + tl.arange(0, BLOCK_SIZE_D)
    x_mask = tl.arange(0, BLOCK_SIZE_D) < D
    x = tl.load(x_ptr + x_offsets, mask=x_mask, other=0.0).to(tl.float16)

    acc = tl.zeros((BLOCK_SIZE_D,), dtype=tl.float32)

    for m in range(0, M):
        router_weight = tl.load(router_ptr + pid_b * S * M + pid_s * M + m).to(tl.float32)
        if router_weight > 1e-4:
            gate_offsets = m * D * D_FF + tl.arange(0, BLOCK_SIZE_FF)[:, None] * D + tl.arange(0, BLOCK_SIZE_D)[None, :]
            up_offsets = m * D * D_FF + tl.arange(0, BLOCK_SIZE_FF)[:, None] * D + tl.arange(0, BLOCK_SIZE_D)[None, :]
            w_gate = tl.load(w_gate_ptr + gate_offsets).to(tl.float16)
            w_up = tl.load(w_up_ptr + up_offsets).to(tl.float16)

            h_gate = tl.sum(x[None, :] * w_gate, axis=1)
            h_up = tl.sum(x[None, :] * w_up, axis=1)
            h_act = (h_gate * tl.sigmoid(h_gate)) * h_up

            down_offsets = m * D_FF * D + tl.arange(0, BLOCK_SIZE_D)[:, None] * D_FF + tl.arange(0, BLOCK_SIZE_FF)[None, :]
            w_down = tl.load(w_down_ptr + down_offsets).to(tl.float16)
            h_out = tl.sum(h_act[None, :] * w_down, axis=1)

            acc += router_weight * h_out

    out = x.to(tl.float32) + acc
    tl.store(out_ptr + x_offsets, out.to(tl.float16), mask=x_mask)
```

**已知缺陷**：该 kernel 使用逐元素乘法替代矩阵乘法，指针偏移逻辑混乱，不可直接编译运行。

## 4. 梯度隔离与权重重组训练

由于多个模型属于不同分布（如 Code、Vision、Math），直接在同一个计算图中回传梯度会导致路由网络 $G(x)$ 的方差爆炸。

- **权重维度重组**：将 4 个模型的 FFN 权重在物理内存上 torch.cat 成一个大矩阵，形状为 $[4, 11008, 4096]$。
- **参数冻结**：将 $W_{gate}, W_{up}, W_{down}$ 的 requires_grad 设为 False。
- **仅训练门控与归一化**：唯一可训练的参数是 Router 矩阵 $W_{router}$ 以及 LayerNorm 的 $\gamma, \beta$。

### 4.1 方差正则化 Loss

强制路由权重在全局 Batch 上的分布尽量均匀，防止退化为只使用某一个模型：

$$ L_{total} = L_{LM} + \lambda \cdot \text{Var}\left(\frac{1}{B \cdot S}\sum_{b,s} \alpha_{b, s, :}\right) $$

**已知缺陷**：最小化此方差会强制每个 token 的路由权重趋于相同，导致路由网络收敛到平凡解。

## 5. 工程实施限制与瓶颈

- **寄存器溢出**：若 $D=4096, D_{ff}=11008$，直接加载完整权重矩阵会超出单线程块的 SRAM 上限。必须将 $D_{ff}$ 分块（Tiling）。
- **权重驻留 HBM 开销**：4 个 7B 模型的 FP16 权重需要约 56GB 显存。单卡 4090（24GB）无法承载，必须进行 INT8/INT4 量化，或使用 NVMe 直接 I/O 异步加载。
- **层间状态不同步**：若第 1 层由 Code 模型主导，残差流分布会发生偏移。直接送入第 2 层的 Vision 模型 Attention 时，可能会因分布不匹配导致输出 NaN。需要在每个融合层之间插入一个极小的 RMSNorm 进行分布对齐。
